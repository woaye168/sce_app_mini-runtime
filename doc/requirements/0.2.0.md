# 0.2.0 需求：真 0 依赖脱机运行时（服务端修复 + 载荷自举 + 工程化收尾）

> 日期：2026-08-21
> 状态：开发中
> 前置：0.1.0 已交付（完全脱机 B 模式调试链路跑通，见 0.1.0.md 与 research/scegame-reverse.md §7-§10）

## 1. 背景

0.1.0 证明了链路的可行性，但实测暴露两组问题：① **局起了但服务端逻辑没真正跑**（不刷怪、背包/装备操作无效）；② 工程化欠债（载荷依赖本机 tester 安装、Python/Rust 工具混用、仓库混入无关文件、未上 GitHub/CI）。

0.2.0 = 把「能跑」变成「真正能用、能分发、能维护」。

## 2. 范围

### 2.1 服务端逻辑未运行修复（最高优先级）

**现象**：客户端进局正常（场景渲染/UI/文字），但不刷怪、背包加装备等服务端行为无效。

**已知线索**：早前实测中 host 数据同步到达客户端时 lua 报 `服务器发送了没有处理者的消息`（Sync_PlayerList/Sync_BagData/Sync_ShopData 等）；控制连接持有期间可持续收 `NotifyEditorLog`（host 服务端日志推送通道，0xF00C）。

**工作**：
- 用 NotifyEditorLog 通道抓取远端局服务端 lua 的启动/报错日志（CLI `debug start --hold <秒>` 保持控制连接并 dump host 日志）。
- 对比编辑器调试局的服务端行为差异（上传文件集差异：我们 1241 全量 vs 编辑器增量 311；EditorStartGame 字段差异）。
- 修复并回归：刷怪、背包/装备、商店（云变量）全部可用。

### 2.2 载荷 0 依赖化（去 tester/编辑器安装依赖）

**目标**：载荷获取不依赖本机任何官方软件安装（不装编辑器、不装 tester/星火对战平台 也能获得运行时）。

- 研究官方下载渠道（updater/OSS：`sce-maps-pd.oss-cn-shanghai.aliyuncs.com/...` 包 URL 模式已实测；引擎二进制渠道待逆向——tester 安装包/编辑器安装包的官方下载点）。
- 实现载荷自举下载（凭证签名 HTTP，按 api_pak_version.json 注册表选版本——**版本跟随星火编辑器服务端更新**，更新检测 = 拉注册表比对）。
- `assemble_runtime.ps1` 去掉 `D:/sce_pc_tester` 扫描等残留硬编码（0.1.0 已改推导式，本项收尾为「下载优先、本机复制兜底」）。
- 截屏等能力已自持（WGC），确认无外部依赖。

### 2.3 全项目自检与 0 依赖优化

- 审查所有代码路径对编辑器安装的隐式依赖（locate.rs 在 CLI auth import 中的角色、GUI 默认参数等），明确「有编辑器只是增强、无编辑器全功能」。
- 凭证 userid 自动补全（引擎登录一次回写凭证库），去掉手动 `--user`。

### 2.4 仓库清理与结构重组

- 删除误入仓库的 `星火对战平台.exe`（根目录）等无关文件。
- 重组：examples/（Rust 工具）、doc/、src/ 结构对齐生态约定（参考 sce_app_editor-patch）。

### 2.5 examples 工具 Rust 化

- Python 工具全部改写为 Rust（cargo examples / 或独立 bin）：proto_extract、find_xref、disasm_at、protocol_parse、analyze_capture、decode_kid、restore_game。
- frida_capture 评估：能 Rust 化（frida crate）则转，不能则归档抓包产物+文档说明，删除 Python 脚本。
- 完成后仓库零 Python。

### 2.6 GitHub 仓库与 CI/CD

- 创建同名私有仓库 `woaye168/sce_app_mini-runtime`，提交全部代码。
- 走通 release.yml（tag 触发）：构建 exe + app-release.json（应用市场分发链，同生态其他应用）。
- 打 tag v0.2.0 出包。

## 3. 验收标准

1. **服务端完整可用**：对 test_res002 起局后，刷怪出现、背包加装备生效、商店购买生效（截屏 + host 日志双证）。
2. **0 依赖装机**：删掉本机 tester 目录引用后，`assemble`（下载模式）能从官方渠道拉回完整载荷并起局成功。
3. **版本跟随**：官方注册表版本号变化时，载荷更新能拉到对应新版本包。
4. 仓库无 Python、无无关二进制，结构清晰。
5. GitHub CI 绿，Release 有 v0.2.0 包（exe + app-release.json）。
