## 三个突破口假设（本轮起手线索）

### 线索一：服务端联动假设（★主线）

之前模型/特效/图集子图的所有失败探针全部打在**客户端**。新假设：服务端 StateGame 才是模型/特效/单位创建的权威入口，客户端只做同步显示——「客户端一直不成功，是不是因为服务端没有？」

- 依据：`doc/research_task/loaded_modules_server/draft_v2/`——服务端 `_G` dump 5121 函数路径 / 373 类；common-base-game 15 个模块全部引擎内嵌（客户端无对应面）；`base.game` 130 键、`score` 28 函数、引擎内嵌 TSTL 类族是客户端完全看不到的能力面。
- 行动：把 draft_v2 五份分组文档当作服务端 API 地图，筛选 actor/model/effect/unit/scene 相关函数与类，写**服务端探针**在 test_res002 实测；服务端创建 + 客户端观察显示，做双端联动实验矩阵。
- 关键对照：render-06 已证「单位换模型必须真实单位（负 id preview 无效）」——真实单位恰是服务端权威创建的对象，服务端侧 `unit:change_model` / actor 创建链可能天然成立。

### 线索二：PascalCase 漏网（双名注册）

`doc/research/pak-io-native.md` 先例：引擎对每个 io 函数同时注册小写与 PascalCase 两个名字，isolation 只阉割小写——`io.ExtractPakFile` 等原生版线上直接可用，绝对路径随便传。

- `doc/research/common-table.md` 记载「双名注册（小写/PascalCase 同名函数并存）」是引擎普遍机制（common 全局表 524 条注册项）。
- 行动：对照 common-table 注册表 + script-199 isolation.lua 阉割清单（包装类/置 nil 类都只写小写名），枚举 `ui.*`、`game.*`、`common.*` 中**被阉小写但 PascalCase 漏网**的函数；对疑似函数做 PIE 实测矩阵（存在性 → 签名 → 行为）。
- 思路要灵活：不止 io——渲染/资源加载/actor 相关的原生函数都可能在 PascalCase 侧漏网。

### 线索三：图集子图存量通道盘点

- render-07：C# 层存在 `Sprite2D.TextureRect` 源矩形能力（lua 未暴露，managed dll 已解密逆向）。
- render-15：'@gameui' 包 lua 已定位解密（62 个明文组件源），uiscene.lua 证实 RenderTarget=bind 属性转发——组件源码里可能还有未被注意的属性转发通道。
- render-08：UI 控件 UV 矩阵全证伪（染色归因法），三通道生产排序已有结论——不要重复踩。
- render-16：scene 控件 name 命名空间已破解（model=单位表节点名/particle=特效表节点名）。
- 行动：通读 '@gameui' 解密组件源 + imgui 通道（render-03/12 线上已实证不崩）找 image/texture 源矩形相关 bind；2.0 WasiCore TextureRect 仅作语义参考（1.0 lua 项目不可用）。

## 实测方法与工作约定（沿用前序任务，逐条有效）

- **不盲信已有知识**：research 已有结论只是线索，验证不符就确认后更新原文档。
- **测试项目纪律**：测试项目 = `test_res002`（`c:\Users\woaye\Documents\SCE Projects\test_res002`），可随意改代码但**不要提交 git**；探针写 `.bgd/src/{server,client}/`（如 `test/` 子目录），**禁止直接改 `script/`、`ui/script/`**（会被构建管线覆盖）；**测试完不要清除探针**——后续探针需要归档整理。
- **事件与入口**：服务端探针挂 `玩家-连入` 事件（范式见 `test_res002/.bgd/src/server/test/url_demo.lua`）；客户端入口 `.bgd/src/client/init.lua`。
- **日志**：只用 `log.info`（print 不一定落盘）；服务端日志在**停止调试后才刷新**。
- **异步**：`base.wait(ms, fn)` 需回调；耗时/网络 API 走协程（`co.async` 范式）；写类 API 必须协程内（服务端实测结论）。
- **线上验证通道**：MCP `publish_project` 发布 pak → `tester_1089.exe -game=<图> -tag=test -ai_test=1` 免交互进真局（参数必须 `-key=value` 形式）；线上 B 模式无 Entrance（云变量黑洞），但渲染类实验不受影响。
- **frida 坑**（已沉淀，直接采信）：模块名大小写敏感；attach 前必须核对进程 Path（PIE 残留进程同名 sce/SCE 会给假数据）；frida17 `Process.getModuleByName`；3 字节 call 拒钩；`readUtf8String(N)` 遇 NUL 抛错；真局 themis 挡 attach（DeviceAttachError）。
- **MCP 截图**：单张约 30s，短窗口实验要留足时长；视觉实证一律双截图对比。
- **调试卫生**：调试完关闭已启动的客户端/编辑器/mini-runtime；起局加 `-width=800 -height=540` 省 token。
- **引擎 lua 坑**：不接受 `|` 前缀注释行（整卷判死），外部文件拷入前先清洗。
