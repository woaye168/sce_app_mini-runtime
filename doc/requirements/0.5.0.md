# 0.5.0 需求：真本地 host（自研逻辑项目）——ZCompress 复刻 + GameHost 编排

> 状态：规划中（2026-09-02）
> 前置：0.4.0（自建 host 中继模式：TCP 控制面透传 + UDP KCP NAT + 全流量 capture，双链路实证进局）

## 背景

0.4.0 交付的「本地自建 host」是中继形态（本地门面 + 云端芯），玩法仍跑在云端。2026-09-02 的研究突破把「真本地 host」从不可行拉回到可行（详见 doc/research/self-host.md §8 B+ 路线、scegame-reverse.md §13）：

1. **会话面已无密码学障碍**：h2c「加密」翻案 = ZCompress 自研 Huffman 压缩（无密钥，纯格式）；c2h 全明文；玩法消息体 = cmsg_pack（msgpack 变体，VM oracle 已逐字节互验）。
2. **服务端引擎本体对本类项目不需要**：test_res002 服务端 native 面仅 6 类（event_register 事件注册 / ui.proto 收 / ui 发（game:ui 广播 + player:ui 定向，算一类）/ auxiliary.get_player_id / player:get_nick_name / log），游戏逻辑全为自研 lua。
3. **server VM API 面已 oracle 取证**（server_common = `@common` 根、server_lua_plus = `@lua_plus` 根、base 977 键、base.game 130 方法）；server_common 本地不可得但可用 script@199 包近似改造。

目标：对「服务端逻辑全自研」的项目（以 test_res002 为验收项目），实现**完全脱机的本地 host**——编辑器「调试(本地服务器)」/ `debug start --host local` 接入后，不 assign_host、不联云端，玩法真实可玩。云端/中继模式保留可选。

## 游戏服务端逻辑来源（关键认知，防执行者误判）

> 完整链路（上传 → 双通道构建 → 下载加载）见 [map-distribution-chain.md](../research/map-distribution-chain.md)（2026-09-02 条目级实证），本节是要点。

2. **server VM 上跑的 `@p_55a3/bgd_game_server/**`（0.4.0 oracle 实证）来自调试控制面上传链**（本地 staging → 0xF004/0xF008 → host），不是下载来的。即：官方 host 的服务端逻辑也是"谁调试谁上传"。
3. **本期服务端逻辑 = 源码级自有**：验收项目 test_res002（`c:\Users\woaye\Documents\SCE Projects\test_res002`）的服务端逻辑就在我们手里——**项目根 `script/` 目录 = 服务端脚本整树，入口 = `script/main.lua`**（编辑器/构建链生成的包装入口：@common + 依赖库 + 项目 main 原文 + 触编模块 + init_units；其中 `bgd_game_server/`/`bgd_libs_server/` 是 bgd 框架构建产物目录名，泛化结构见 map-distribution-chain.md §3.1）。经现有 staging 链（`src/core/staging.rs` 白名单已含 `script`/`src`/`table`/`scene` 等）落盘/上传即可供给自研 host，**无需也不可从任何官方 pak 提取服务端逻辑**。

**R4 实际过程中所需**（全部已在手边，无外部依赖）：test_res002 完整项目（源码 + 数编 table + scene + res + libs.json）→ staging.rs 白名单生成上传包（0.4.0 既有链路，312 文件实证）→ 自研 host 控制面接收落盘 → GameHost 编排加载。跑别人的图 = C 路线，不在本期范围（见不做清单）。

## 验收标准

- [ ] **R1 ZCompress 位流格式复刻（核心攻关）**：Rust 实现 decode + encode，与引擎实现互验一致。方法双路互证：① sceengine.dll 反汇编 ZCompress 编解码函数（源路径已知 `Client/src/Game/Network/ZCompress/`，字符串锚点 `[Compress(%x)]` / `rebuild huffman tree finished`）；② 已知明文对照（VM 内 `cmsg_pack.pack` 造明文 → 中继抓压缩后字节）。开工第一步先侦察是否存在"不压缩"标志位/开关（`[kcp] %x fec switch %d` 显示 FEC 有运行时开关）——但无论结论如何，**decode 必须完成**（R2 依赖），encode 在开关实机证实存在时可走开关旁路（见执行纪律）。**量化验收**：以附录 C 基准 capture 的全部 h2c 消息为样本集，decode 100% 通过；encode(明文) → 自实现 decode 往返一致。**注意**：VM 内没有可直接调用的 ZCompress decode/encode API（勿找）——encode 的引擎侧终验路径 = 自研 host 用自实现 encode 发包 → 真客户端 → hook `on_ui_message` 对账明文（该 hook 手法已实证，附录 D）。
- [ ] **R2 中继解码器**：kcp_capture_parse 升级为全解码——c2h 流重组 + protobuf 外壳 + cmsg_pack 内层直出协议名/参数；h2c 经 R1 解码后同格式直出；跟踪 on_ui_message_new 的 type_id↔type_name 映射表。**量化验收**：对基准 capture 全量解码，对照原始 jsonl 逐消息对账零丢失；任意一局 capture 能完整回放双方协议时间线（Req_*/Sync_* 人眼可读）。**产出物（R3 的输入）**：h2c 应用层消息表 + 登录→进局全消息序列（host 侧每个阶段该发什么、应答什么），落盘 scegame-reverse.md §13。
- [ ] **R3 最小本地 host 服务（壳 host 能力基座）**：Rust 实现**双端面**——
  - 会话面：KCP 服务端（CE1 握手/conv 下发/PUSH/ACK/重传/3B 流分帧）+ 登录（msg 1 及其应答）+ 心跳（0x2000）+ 时钟同步（0xF100）+ UI 消息（0x7006 cmsg_pack 双向）。host 侧消息序列以 R2 产出为唯一来源。客户端会发的 0x6011（UI 视图同步）与 msg 5（状态）**收到即弃**（host 无需处理，但须明确丢弃不报错不断连）。
  - 控制面：TCP 服务端应答 0xF000 段——EditorLogin 应答 + 逐文件上传（每文件 0xF010 ack，编辑器本地接入纪律）+ 起局指令 + 0xF00C 日志通道（让编辑器控制台有日志可读）+ 0xF01F 编辑器心跳（应答或安全忽略）+ 0xF01B 停止调试/销毁通知（**停局 teardown**：收 0xF01B 后清理本局会话状态、可接下一局）。起点 = sce_app_editor-patch `examples/host_stub.rs`（控制面服务端全链已验证版本，附录 B）。
  **host 进程生命周期**：编辑器侧没有任何按需拉起本地 host 的逻辑（self-host.md §2 实锤）——PIE 入口下须先经 `host start`（或 GUI 调试页）把自研 host 起起来再点「调试(本地服务器)」；`debug start --host local` 入口则由 mini-runtime 进程常驻承载（0.4.0 既有模式）。
  **量化验收**：自研 host 单独监听 5003/5053（不 assign_host、不联云端），官方客户端进图到大厅/场景渲染（玩法缺席可接受）——login 成功、加载进度 100%、心跳保活 ≥5 分钟不断线、capture_game 截图确认渲染；编辑器 PIE 停止调试后 host 正常 teardown 可接下一局。
- [ ] **R4 GameHost 编排复刻（真本地服务端）**：lua 侧 host 运行时——加载链（@common ≈ script 包改造 + @lua_plus + 地图包 bgd_game_server）+ 事件泵（游戏-帧/玩家-连入/断线）+ 消息路由（0x7006 → base.ui.proto 分发；game:ui/player:ui → 0x7006 回包）+ 6 类 native shim。**开工先决决策项**（记入当期提交说明）：① lua 宿主选型（Rust 内嵌 mlua/lua54 或独立 lua VM 进程）；② lua 运行时物理落盘目录（主 crate 资源内嵌 还是 项目 staging 目录生成）。6 类 shim 的取证出处（oracle dump 行号）须留档进 self-host.md §11（server VM oracle 主场，§13 只放 KCP 会话层主题）；shim 面的完整清单核对基准 = 客户端 script-199 `common/base/server.lua:184-234` 的 native 调用点。**量化验收**：test_res002 全脱机进局——玩家上线、移动/攻击/技能/背包/商店协议全通；协议 checklist 化（把 test_res002 实际用到的 Req_*/Sync_* 列成表逐条勾验），对照中继抓包的云端行为逐条比对。
- [ ] **R5 宿主集成与三态 UI**：调试页 host 模式三选（云端直连 / 中继观测 / 真本地），GUI 与 CLI 严格一致；CLI `debug start --host cloud|relay|local`（**现状是 cloud|local 且 local=中继**——本期引入 relay 值承接中继，local 改为真本地；host 模式从不落盘（内存态，无配置迁移问题），需处理的只是用户脚本/文档里 `--host local` 旧语义的变更，Release notes 与文档明确标注语义切换）。默认态 = cloud（不改变现有用户默认行为）。真本地模式的凭证依赖去除（不 assign_host 即不需凭证——注意与「客户端仍需 login=1 凭证进游戏」区分：去除的是控制面 assign 凭证，客户端登录凭证文件仍由现有 auth 链提供）。验收含编辑器 PIE 入口：编辑器「调试(本地服务器)」菜单接入自研 host 全流程可玩。触点文件：`src/ui/debug.rs`（下拉两项→三项）、`src/main.rs`（CLI 值域）、`src/core/debug.rs`（HostMode 枚举）。文档同步 AGENTS.md + self-host.md + scegame-reverse.md。

## 执行纪律（本版本为技术攻坚，不设回退路线）

- **R1~R5 全部为必须项，不允许任何形式的范围缩减**。卡顿时唯一允许的动作是加深研究（补抓包样本/反汇编/VM oracle/实机对照），不允许把「退而求其次」当成交付。
- **顺序即依赖**：R1 → R2 → R3 → R4，R5 在 R3/R4 之后收口集成。R2 依赖 R1 的 decode；R3 的 host 侧消息序列以 R2 产出为唯一输入；R4 依赖 R3 的双端面与 h2c 发送能力。不允许跳序并行开工。
- 「不压缩开关」的验证只是 R1 的第一步侦察；**即使开关存在，R1 的 decode 仍必须完成**（R2 中继观测依赖），encode 方可走开关旁路，且开关必须实机验证真实存在才算数。
- 每完成一项 R，当次提交内同步 self-host.md / scegame-reverse.md / AGENTS.md（不允许先实现后补文档）。

## 整体验收（R1~R5 之外，版本出口闸）

- **「完全脱机」客观定义**：载荷已预先同步完成（断网下不触发 payload sync）+ 机器断网（或防火墙全阻断）+ 无任何云端 assign/host token 凭证的条件下，`debug start --host local` 与编辑器 PIE 均能完成进局并正常游玩；同时抓包/日志确认全程零云端外联（无 assign_host、无 OSS、无 debug host 连接）。**注意**：客户端进游戏仍需本地凭证库提供的 user_info 注入（login=1 自动登录闸门，与 host 模式无关，0.3.0 既有机制）——「去除凭证」仅指控制面 assign 凭证。
- **回归验收（0.4.0 链路不退化）**：`--host cloud` 与 `--host relay`（中继）两条既有链路在 R5 落地后各自完整跑通一次进局。
- **发布条件**：R1~R5 全部勾选 + 整体验收通过 + 文档同步完成，才可打 tag 出包。

### D. 环境/工具链坑（已踩过，勿重蹈）

- **cargo examples 本机受阻**：dev-deps 的 frida-sys 需 libclang（本机无），任何 example 都编译不过。绕法：零外部依赖的工具用 `rustc --edition 2021 -O` 直编（先例见 kcp_capture_parse.rs 头注释）；需要第三方库的分析工具建独立小 crate 放 `test/temp/`（先例 `test/temp/inflate_test/`）。**注意：主 crate（src/）加普通依赖不受此限**，R1/R3/R4 在主 crate 内正常加依赖。
- **CLI 输出不可见**：exe 是 windows 子系统，管道下 stdout 丢失——用 `Start-Process -RedirectStandardOutput/-RedirectStandardError` 落文件再读。
- **引擎 VM oracle**：编辑器在线时经 sce_app_editor-patch MCP（`lua.eval` 游戏 VM / `lua.run_lua` 编辑器 VM / `start_debug` 起 PIE / `capture_game` 截图）——cmsg_pack 互验、on_ui_message hook、探针回读、R3/R4 截图验收都走这条。用法见附录 A 的 mcp-integration-guide.md。
- **编辑器管线纪律**：控制面失败必须回 0xF001 result≠0；编辑器本地接入逐文件等 0xF010 ack（缺一即卡死）；Start-Process 参数含空格路径要元素内嵌引号。

## 关键实证（0.4.0 研究期产出，本期直接可用）

- KCP 会话端口 = 控制端口 + 50（引擎硬编码）；CE1 握手族（SYN/SYACK/ACK/SYNACK + REP/DISCONNECT/TIMEOUT/PAUSE/RES 控制魔法）。
- c2h 消息表：1=登录 / 3=加载进度 / 0x2000=心跳 / 0x6011=UI 视图同步 / 0x7006=玩法协议 / 0xF100=时钟同步。
- cmsg_pack = msgpack 变体（字符串走 bin 家族 0xc4）；`pack({type,args})` 与抓包逐字节一致。
- h2c = ZCompress（每消息内嵌 Huffman 树头；熵 7.36；树头 68% 消息共享首 5 字节）。
- server VM：`_G.__IN_HOST__=1`、`base.game.message/ui` 为函数点、`package.loaded` 368 模块（@common/@lua_plus/@p_55a3 三层）。
- 编辑器管线纪律：assign/连接失败必须回 0xF001 result≠0（防 update_host co.call 悬挂）。
