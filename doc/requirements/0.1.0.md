# 0.1.0 需求与技术设计：脱机登录与调试（完全脱机 · 方案 B）

> 日期：2026-08-21（v3 定稿：基于当日完整逆向实证重写）
> 状态：开发中（核心链路已实测跑通，见 §6 里程碑）
> **核心约束：登录与调试全程不碰星火编辑器；机器上没有安装编辑器也必须能跑。**
> **方案选型：B（本地工程调试模式）——无大厅 UI，直接加载本地未上传、未打包的游戏工程目录调试。方案 A（对战平台大厅 + 服务器 pak）明确不采用。**

## 1. 背景与目标

`bgd_sce_tools` 生态应用 `sce_app_mini-runtime`（脱机运行时）。业务价值：游戏作者在没有/不开星火编辑器的环境里（CI 机、二开工具机、玩家排障机）也能登录并完整调试本地项目。

**0.1.0 交付两件事：**

1. **脱机登录**：自实现 TapTap OAuth2 device flow + 凭证库（多账号存档/切换/验证），凭证可导入本机编辑器已有凭证（只读，不踢编辑器）或扫码新建。
2. **脱机调试（方案 B）**：对本地项目目录（未上传、未打包的源码工程）拉起官方调试局——本地渲染/客户端逻辑在本机自托管运行时执行，服务端逻辑由官方远端调试 host 执行（**v13 云变量/玩家存储在线可用**，这是「完整调试」的应有之义）。

**边界（明确不做）**：脱机发布（0.2.x）、多开并行、画面截取、编辑器 GUI 功能、wasm/C# 项目（触编 v2 C# 侧，见 §7）。

**「脱机」的精确定义**：不安装、不启动、不读取星火编辑器任何组件；但**必须在线**——调试需要凭凭证请求官方线上服务（assign_host 分配调试 host、host 上跑服务端 lua 并提供云变量）。完全离网的「单机调试」不是 0.1.0 目标（官方架构如此，见 §3.2）。

## 2. 系统架构设计

### 2.1 总体拓扑

```
sce_app_mini-runtime（Rust/egui 宿主，本应用）
  │
  ├─ 凭证库（exe 旁 sce_app_mini-runtime.credentials.json，多账号）
  │
  ├─ 调试编排（debug session）
  │    ① 项目装载：项目目录 → 暂存目录（复制白名单 + 触发器 lua 生成）
  │    ② assign_host：HTTP 签名 POST → 远端调试 host ip/port/token
  │    ③ 控制协议客户端：EditorLogin → UploadDelta(逐文件 SendWriteFile) → EditorStartGame
  │    ④ 拉起客户端子进程：scegame.exe -env=game ... -map_path=<暂存> -host_ip/port -user=<userid>
  │    ⑤ 观测：解析 runtime/logs/{game,lua}/ 日志；停止 = taskkill 进程树
  │
  └─ 运行时载荷目录 runtime/（自托管，随应用分发或首次运行自举下载）
       ├─ scegame.exe + 引擎 dll（见 §2.2 清单）
       ├─ Update/editor-pd.spark.xd.com/Res/<核心包>（见 §2.2 清单）
       └─ User/user_info-editor-pd.spark.xd.com.json（启动前由凭证库注入当前活动凭证）
```

关键事实：**调试客户端是独立的官方引擎进程（scegame，tester/BuildPCBox 构建，48MB 纯 native，无 .NET 依赖）**，与编辑器无文件/进程依赖；它通过 argv 接收登录态（`-user` 数字 userid）与地图路径（`-map_path` 本地暂存目录），直连远端调试 host。

### 2.3 登录态与鉴权机制（调试时序）

**凭证三要素**（`user_info-<环境>.json` 明文）：`token`（mac_key$kid，token_type 11=编辑器）+ `login_token`/`login_token_secret`（HTTP 签名对）。签名：`md5(noise\ntime_str\ncontent_md5\nlogin_token\nlogin_token_secret)`。

**调试登录态透传时序**（已全部实测验证）：

```
[mini-runtime]                     [官方线上服务]                [远端调试 host]      [scegame 客户端]
     │ ① 注入 user_info-<env>.json 到 runtime/User/                    │                    │
     │ ② POST http://editor-pd.spark.xd.com:9007/api/v1/assign_host   │                    │
     │    （login_token 签名 + api_version=13）                        │                    │
     │ ◄──────── {host_info:{ip,port,token}} ──────────              │                    │
     │ ③ TCP 控制连接: EditorLogin(token)                              │                    │
     │    UploadDelta: SendWriteFile 逐文件上传项目（p_xxxx 命名）      │                    │
     │    EditorStartGame ─────────────────────────────► 起服务端局    │                    │
     │ ④ spawn scegame -env=game -host_ip=<ip> -host_port=<port> ──────────────────────► │
     │    -user=<userid> -map_path=<暂存目录> ...                                         │
     │                                                                 KCP 直连 ◄────────│
     │                                                            login(userid)           │
     │                                                            收场景/单位/云变量同步    │
```

- **userid**（数字，如 38672742）：来自凭证对应账号（assign_host 响应/编辑器登录日志可证）。
- **控制协议 token**：assign_host 返回的一次性 host_token，仅控制连接用；客户端不带 token（host 按 ip/port+user 认局）。
- **云变量**：服务端 lua 在远端 host 执行，云变量/玩家存储天然在线——这正是 v13「完整调试」要求在线的原因，也是「凭证前置登录」的必要性来源。

### 2.4 本地项目工程加载器（Project Loader）

输入：项目根（含 `project.sce`、`project/map_settings.json`、`scene/`、`script/`、`ui/`、`table/`、`res/`、`config.ini`、`libs.json`）。

处理（对标编辑器 map_starter 的暂存逻辑，`xdeditor/map_starter/init.lua` 实证）：

1. 读 `project/map_settings.json` → api_version（决定引擎/包版本）。
2. 清空白名单复制到暂存目录 `<runtime>/User/debug/<项目名>/`：目录 atmosphere/block/game_hud/i18n/project/ref/res/scene/script/src/table/ui + 文件 config.ini/libs.json/project.sce。
3. **触发器 lua 生成**：编辑器会跑 `trigger_manager.generate_lua_only`（tstl，TS→lua）产出 `ui/script/`。bgd 框架项目直接写 lua（`ui/src/main.lua`），需桥接为运行时期望的 `ui/script/main.lua` 布局；触编 TS 项目则需官方 tstl 工具链（`_m/typescript_to_lua_node_modules`）——0.1.0 先支持纯 lua 项目。
4. 产物即 `-map_path` 的值。客户端运行时按 `<暂存>/scene/default/map.acmap`、`<暂存>/ui/script/main.lua` 等相对路径读取（引擎 `InitBasepath` 实证）。

## 3. 逆向分析结论与关键 API 调用链路

> 详细实录见 `doc/research/scegame-reverse.md` §6/§7（含逐行日志）；此处为结论性摘要。

### 3.1 编辑器「调试」按钮完整链路（Win32_Process 实捕）

1. `星火编辑器.exe`（launcher 外壳）读 `<项目>/project/map_settings.json` → 执行 `version-<api>\SCE -server=editor-pd.spark.xd.com -use_local_res -editor_api_version=13 -generate_and_debug_map -file_path=<项目>\project.sce`。
   - 坑：`-file_path` 必须指向项目内**文件**（project.sce），`GetMapPath()`=dirname(file_path)。
2. map_starter（xdeditor 包）：登录 → assign_host → 项目复制到暂存 → `DebugManager.update_host(ip,port,token)` → `DebugManager.debug_game{map_path=暂存,...}`（native）→ `os.exit(0)`。
3. native DebugManager（sceengine.dll，BuildPC Editor 构建）：TCP 控制连接（libhv）→ EditorLogin → UploadDelta（`SendWriteFile: p_55a3, p_55a3/<相对路径>` 逐文件，p_55a3=项目发布地图 id；host 已有版本的依赖库跳过）→ InformHostLaunchGame(EditorStartGame) → **spawn 客户端** → 控制连接断开不影响 host 局。
4. 客户端进程（实捕命令行，即本方案复用的官方契约）：

```
SCE -env=game -editor_server_debug -editor_api_version=13 -no_update -save_replay -kcp_stream -map_kind=0 -server=editor-pd.spark.xd.com -use_local_res -host_ip=106.14.95.227 -host_port=14416 -local_test -user=38672742 -map_path="D:/sce_online/User/debug/test_res002" -to_download_list="test_res002" -width=2340 -height=1080
```

### 3.2 无大厅模式的初始化时序（lua 层，tester_startup-364 + client_base-78 实证）

B 模式下 **不走大厅/entrance**（`connect_to_entrance` 不被调用）。关键路径：

1. 引擎启动 → 挂包 → `StateGame Open Lua` → `script/common` 入口 → `client_base`（account 读 `User/user_info-<env>.json`）→ `startup/entrance/init.lua` → `startup/entrance/main.lua`。
2. `entrance/main.lua:99-111`：argv 判定——`-editor_server_debug` + `-local_test` → `connect_host_opportunity = CONNECT_HOST_IMMEDIATELY`（**跳过登录按钮/更新等待/大厅**）。
3. `entrance/main.lua:2611-2616`：`base.wait(50)` 后 `lobby.connect_host()`（native Lobby 子系统）——日志 `本地调试, 立即连接本地host`。
4. native：`CreateDebugGame` → GamePlayLocal → `StartGame` → `Connect to game host server, ip:<host_ip> port:<host_port>` → KCP（`-kcp_stream` → useStreamMode:1）→ `GamePlayOnline request login, userid:<-user>` → host login result[0] → 加载 `-map_path` 场景 → `Game host notify start game` → 全量数据同步。
5. 对照（A 模式）：`connect_to_entrance()`（entrance/main.lua:400）连大厅长连接 → token 登录 → app_box——B 模式完全绕过此路径。

### 3.3 自托管实测结论（2026-08-21）

- **scegame（BuildPCBox）可作为 B 模式客户端**：用实捕命令行（复刻到 `Update/editor-pd*/Res` 载荷 + 注入凭证）顶替编辑器 spawn 的客户端，对新鲜 host 局：KCP 连接 ✓ → userid 登录 ✓ → 场景同步 ✓ → 服务端数据（玩家/背包/商店/云变量周期数）全量下发 ✓。
- 对**已销毁的旧局**重连会 `login result[2]` → return_to_lobby（局随客户端断开销毁，需自己起局）。
- **shell 传参陷阱**：PowerShell 会把 `-host_ip=106.14.95.227` 在 `.` 处拆参（ip 变 "106" → wsa:10049），`-server=editor-pd.spark.xd.com` 同理被拆成短名。应用内 spawn 走 CreateProcess 数组传参，无此问题；手动测试须整体加引号。
- 凭证/Update 目录名跟随 `-server` 原值（全名 `editor-pd.spark.xd.com`）。

## 7. 路径 2 线索结论（official_client_deps_dll_package / official_dotnet_bcl_package）

- `official_client_deps_dll_package/23` = 游戏 **C# 逻辑运行时**（GameCore/GameData/GameGraph/GameUI/TriggerEncapsulation/Events，`ui/AppBundle/managed/` 挂载，GameInstance 找 `GameEntry.dll`）——触编 v2 C#/wasm 项目专用。
- `official_dotnet_bcl_package/6` = 内嵌 .NET BCL（CoreCLR 基础类库）。
- **结论：纯 lua 项目（bgd 框架）不经过这条链**（客户端 lua StateGame 直跑），0.1.0 不引入；若未来支持 wasm/C# 项目再启用（届时这两个包是「脱机跑 C# 游戏逻辑」的关键载荷）。
